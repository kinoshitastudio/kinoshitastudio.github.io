# SAKUJI 回帰テスト

    bash sakuji/_test/run.sh        # 56項目（1枚の画面で測れるもの）
    bash sakuji/_test/idb/run.sh    # 読み込んだ書体がリロードを越えて残るか

⭐ **本体（index.html）は1行も触らない。** コピーの末尾に `regression.js` を差し込み、
headless Chrome で読んで結果を取り出す。テスト用のコピーは終わったら消す。

⚠️ `localhost:8090` が sakuji フォルダを配信していること（file:// だと CDN と localStorage が使えない）。

## 何を守っているか
今日（2026-07-31）に踏んだ型を、そのまま項目にしてある。

- シェイプ14種が図形を返す ← 菱形が `remove()` の短絡で `true` を返していた
- 掴む単位は「束ね」 ← 文字が1クリックで選べなかった
- 粒が **元の形／組み方／かけた設定** を覚える ← リロードで記憶が落ちていた
- 保存は粒の実体を持たず作り方だけ、**取り出したあと画面に粒が残る**
- 作り方から組み立て直せる
- SVG に器と viewBox が付く（`<g>` は被せる／`<svg>` は注入／既にあれば触らない）
- Undo が同じ状態を二重に積まない
- 効かない項目（階調・網）がグラデ塊のとき薄くなる
- **下敷き（写真）は専用の層に居る**（2026-08-24）← 枡と同じ層に敷いていたので
  枠の白地の下に潜り、さらに枡を描き直すたびに消えていた＝「読み込んだのに出ない」

## 効くことの確かめ方
わざと壊すと、壊した箇所を名指しで落ちる。

    FAIL シェイプ14種すべてが図形を返す   [diamond]

⚠️ 落ちないテストは意味がないので、項目を足したら **一度わざと壊して赤くなるか**を見ること。

## `idb/` ── リロードを越えるかを測る（2026-08-22）

1枚の画面では「開き直す」が作れない。だから **同じプロファイルで Chrome を2回開く**。
① 作った .ttf を**本物の読み込み口**（ファイル選択）から入れる → ② 開き直して戻るかを見る。

🔴🔴 **`--virtual-time-budget` を使わないこと。** あれは**時計を止める**ので、

- `IndexedDB` が返らない（`fdbAll` が永久に待つ）
- `performance.now()` が全部 **0ms** になる
- **rAF が回らない**（＝画面が描き直されない）

2026-08-21〜22 に「headless では IDB は見られない」と結論したのは、これが原因だった。
⚠️ 旗を外すと `--dump-dom` は読み込み直後に吐くので、結果は `logsrv.py`（127.0.0.1）へ POST して受け取る。

⚠️ **`placeText` は headless では字を作れない**（もとから入っている書体でも 0字）。
だから「戻した書体で字が置ける」は**判定にしない**。代わりに
`fonts.check` と **幅が変わるか**（その書体 100.0 / monospace 50.0）と
**opentype でグリフが取れるか**（134命令）で見る。
