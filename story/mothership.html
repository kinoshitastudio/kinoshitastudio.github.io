— 開発日記 / the honest version

AIが変わっても、
設計は、手元に残す。

これは、きれいな設計書じゃない。
「AIが変わったら成果どこ行く？」の引っかかりと、
話しかけたら本物のノードが建った日と、詰めの精度の話。
——Figmaプラグイン Mothership を作った、本人の裏話。

木下スタジオ · 個人開発 Figmaプラグイン · Claude Code No-MCP · 原本(JSON)中心 mothership を見る ↗
#01🛰 引っかかり

便利なのに、ずっと引っかかっていた。

AIでFigmaを動かす道具は、この1〜2年で一気に増えた。便利だ。でも使いながら、ある不安が消えなかった。

「AIが変わったら、この成果は、どこへ行く？」

多くの道具は、AIとの"接続"の上に成果が乗っている。接続が切れれば、モデルが変われば、資産は消える。ほしかったのは逆だった。AIが何であっても、手元に残る設計。

#02📦 名前

中心に、1枚の「原本」を置いた。

レイアウトも、情報構造も、タイポも、ルールも——全部、ひとつの JSON（原本）に。すべてがこの一枚からつながる。

WHY原本が、母艦。AIは乗り換え可能なクルーにすぎない。だから Mothership——母艦、と名付けた。
#03✨ 手応え

「料金表を」と言ったら、本物のノードが建った。

話しかければ、設計が生まれる。「3プランの料金表を」と言えば、Claude が原本を書き、プラグインが Figma に編集可能な本物のノードとして建てる。画像でもモックでもない、触って直せるノード。しかも MCP は要らない。

#04🧩 割り切り

これは、パワーユーザーの道具になった。

動かすには Claude Code（Pro/Max）＋ Figma ＋ Node ＋ relay 起動が要る。Figmaプラグインのサンドボックスの制約もある。

詰まった「誰でもワンクリック」には、まだ遠い。そこは正直、割り切った。

最初に深く刺さる人に、深く刺さればいい。まずはそこから、と決めた。

#05🔁 生成で終わらせない

つくるだけじゃなく、整えて、貯める。

生成だけじゃない。上流——ペルソナ・ジャーニー・フローまで話すだけで生成できる。さらに、ボード上の"すでにある"どのフレームも、命名・余白・トークン化で整え、蓄積し、自動化する。

芯判断するのは人。蓄積されるのは知識。継承されるのは、設計思想。
詰めの精度こそが、価値。
使うほど鋭くなる、終わらないループ。
#06📐 精度

プロは、余白とタイポで値踏みする。

プロが見るのは、タイポの精度・余白・プロポーション。そこが甘ければ、手で描いた方が早い＝使われない。

だから参照を重ねて px 単位で詰める。詰め切ったパターンはライブラリに貯まり、次が速くなる。この終わらないループが、KVの金の ∞ だ。

#07🚀 公開、そしてこれから

2026年6月、Figma Community に出した。

今日は「チャットから Figma を生成する道具」に見えるかもしれない。けれど目指すのは、個人や組織の設計知識を、蓄積し・再利用し・育て続けられる環境。

そして最終的には、Figmaプラグインを超えた、判断を積み上げるスタンドアロン環境。琵琶湖のそばで、この母艦を毎日使いながら鍛えている。

芯AIは、そのための翻訳者にすぎない。中心は、いつも人の判断と、原本にある。

つくる前に、"なぜ"を決める。
