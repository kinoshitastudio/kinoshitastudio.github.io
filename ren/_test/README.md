# 連 REN 試験

    python3 -m http.server 8092 --directory ren     # 別の窓で先に配信しておく
    bash ren/_test/run.sh          # 24項目の判定
    bash ren/_test/run.sh shot     # 並べた1コマの絵 → ren/_test/_out.png

⭐ **本体（index.html）は1行も触らない。** コピーに試験を差し込んで headless Chrome で読み、
終わったら消す。

🔴 **差し込む場所が sakuji と違う。** REN の中身は `<script type="module">` なので、
`</body>` の前に別の `<script>` を足しても **中の関数も変数も見えない**。
だから **モジュールの中（`frameAt(0);` の直後）** に入れる。

## 何を守っているか（2026-08-24「並べる」を入れたときに踏んだ型）

- **同時に並べる尺は【いちばん長いもの】**（順に繋ぐ＝足し算）。
  ⚠️ `total()` は書き出しの長さ・目盛り・再生ヘッドが全部見ているので、ここが1か所
- 🔴 **升に対する大きさ**。`sc` は「版面いっぱいに収めた状態＝100」なので、
  升の数で割った値をそのまま入れると絵が升の何倍にもなる（2列で 88 と入れて版面の88%を占めた）
- 🔴 **ずらして並べても版面から出ない**。中心の動ける範囲は**絵の半分だけ内側**（右上が切れた）
- 🔴 **傾けボタンは置き場を消さない**。消すと版面いっぱいに戻って他を全部覆う
- 🔴 **つまみは選んだ1枚だけに効く**。選んだ時にその1枚の値をつまみへ戻さないと、
  2枚目を触った瞬間に1枚目の角度が乗り移る
- **タイムラインも「同時」に見せる**（全部左端から・段に積む）。
  順番の帯のまま出すと画面が嘘をつく
- **素材を足しても、動かした置き方を壊さない**（並べ直すのは押した時だけ）
- **SNS 1080×1350 が出せる**。⚠️ 長辺の刻みが40だったので 1350 が作れなかった

⚠️ 落ちない試験は意味がないので、項目を足したら**一度わざと壊して赤くなるか**を見ること。

## headless の落とし穴

- **動画は headless で作れない。** canvas に `videoWidth` / `videoHeight` / `duration` /
  `currentTime` を足した「動画の札」を使う（`drawImage` はそのまま通る）
- 本体は寸法を `naturalWidth`（画像）／`videoWidth`（動画）で読む。
  canvas はどちらも持たないので、試験側で足しておく
