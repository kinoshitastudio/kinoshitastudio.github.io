Board

"Where Designer's Intuition
meets Hacker's Command."

Now Live — bmboard.studio Chrome Extension — Black Mirror Browser ↗
— Overview

HTMLひとつ。依存ゼロ。ビルドなし。
外部ライブラリを持ち込まず、ブラウザだけで動く
インフィニットキャンバスツール。

描いた図形がターミナルに応え、
コマンドが「魔法」になる——
設計思想そのものをプロダクトに実装した。

bmboard.studio ↗

"ホワイトボードは思考の外部化装置だ。だがUIが思考の速度に追いつかないとき、道具は邪魔になる。
BMBoardは『速さ』と『深さ』を同時に解決しようとした最初のプロダクトだ。"

Kinoshita Studio
Design Philosophy
2026
— Problem & Approach

クリエイターがホワイトボードを使うとき、画面と思考の間には常に摩擦がある。「ちょっとメモしたい」のに、ツールが起動を要求し、クラウドへのログインを求め、保存先を選ばせる。

そのストレスを根本から取り除くために、BMBoardはHTMLひとつのシングルファイル設計を選んだ。ダウンロードして開くだけ。インターネットも不要。ブラウザがあれば動く。

さらに、「描く」という行為にコマンド体系（Terminal Magic）を組み合わせた。テキストボックスに `@spell` と打てば、図形やレイアウトを一瞬で召喚できる。デザイナーの直感とエンジニアのコマンドラインが、ひとつのキャンバス上で融合した。

GIFアニメーション生成、テンプレート展開、自動テーマ切替、パレット管理——これらを外部依存ゼロで実装したことで、BMBoardは「持ち運べる思考空間」になった。

— Tech Stack
Vanilla JS Canvas API No Framework No Build Step Single HTML File GIF Encoder
— Key Features
  • ◦鉛筆ツール — コーナー検出付き quad-midpoint smoothing で滑らかな描線を実現
  • ◦テキストツール — Ctrl+Enter で確定、インライン編集、フォント自動継承
  • ◦Terminal Magic — @spell コマンドでキャンバスに図形・テンプレートを展開
  • ◦GIF on Canvas — 録画・書き出しをブラウザ完結で実行
  • ◦オブジェクト整列 — 選択図形を水平・垂直・均等配置でワンクリック整列
  • ◦テンプレート展開 — よく使うレイアウトをパレットから一発挿入
  • ◦自動テーマ — システムのダーク/ライト設定に追従
  • ◦カラーパレット管理 — よく使う色をワンクリック保存・適用
  • ◦DUP ボタン — モバイルでも選択図形を複製できるタップUI
  • ◦BMBrowser 連携 — Chrome拡張のサイドパネルでBMBoardが起動
— Design Principle
Zero Install Offline First Speed over Feature Open Canvas

Ateli.er

"中庭のような、静かな音楽空間。"

Now Live — atelistudio.com Chrome Extension — Ateli.er Player ↗ Chrome Extension — Ateli.er Clip ↗
— Overview

音楽は消費するものではなく、
空間として存在するものだ。

誰かのチャンネルに流れる音楽と、
静かに並走する。ただそれだけの体験を
Webアプリとして実装した。

atelistudio.com ↗

"Spotifyは音楽を『発見させる』プラットフォームだ。だが私が求めていたのは、誰かの音楽の横に静かに座れる場所だった。
中庭というメタファーは最初から決まっていた——そこは誰のものでもなく、誰でも入れる場所だ。"

Kinoshita Studio
Design Philosophy
2026
— Problem & Approach

現代の音楽ストリーミングは、アルゴリズムによって「消費」を最大化するよう設計されている。次の曲へ、次のプレイリストへ——ユーザーは絶えず新しい刺激を与えられ続ける。

Ateli.erはその逆を設計した。「中庭」というコンセプト。誰かのチャンネルが流れ、あなたはその横に静かに座る。再生カウントが積み上がり、活動グラフが記録される——でも、急かされることはない。

チャンネル制を採用したことで、ユーザーは自分の音楽空間を「場所」として管理できる。BGMのチャンネル、思索のチャンネル、雨の日のチャンネル——その文脈設計こそが、Ateli.erの体験の核心だ。

ローカルファーストの同期設計により、オフライン環境でも自分の投稿・チャンネルデータは保たれる。Supabaseとの同期は「気づかないうちに行われている」体験として実装した。

— Tech Stack
Vanilla JS Supabase PostgreSQL LocalStorage Sync PWA OGP Collector
— Key Features
  • ◦チャンネル — 音楽を「場所」として管理。テーマ別に複数チャンネルを持てる
  • ◦中庭 (Courtyard) — 他ユーザーのチャンネルを ambient 受動再生。並走体験の中核
  • ◦Clip 機能 — YouTube / SoundCloud URLを貼るだけで楽曲登録。OGP自動取得
  • ◦活動グラフ — GitHubスタイルの投稿履歴グラフ。自分の音楽活動が可視化される
  • ◦CONNECT — チャンネル間のリンク機能。共鳴する音楽空間をつなぐ
  • ◦Explore フィード — 全ユーザーの公開チャンネルを横断して発見
  • ◦Player — ambient受動再生専用ページ。Kindle Fireなど常設端末向け
  • ◦ローカルファースト同期 — 事前プル・競合安全・visibilitychange プッシュ
  • ◦招待制→誰でも登録 — 2026年5月より公開、サブスク制は将来候補
— Design Principle
Ambient First No Algorithm Local First Quiet Design

KODOCO

"今日の文脈に、答える。"

Now Live — kodoco.jp
— Overview

「今日どこいく？」に、情報サイトは
答えられない。

天気、子どもの年齢、外出できる時間——
その文脈を読んで1スポットを提案する
子連れおでかけ案内アプリ。

kodoco.jp ↗

"既存のおでかけ情報サイトには、スポット一覧がある。でも私が疲れ果てた週末に必要なのは、一覧ではなく『答え』だった。
選択肢を減らすことが、体験設計においていかに重要か——KODOCOはその実証実験でもある。"

Kinoshita Studio
Design Philosophy
2026
— Problem & Approach

子連れ外出の計画は、なぜか毎回消耗する。「どこか連れていきたい」という気持ちはあるのに、情報サイトを開くと選択肢の洪水にのまれ、気づけば午前中が終わっている。

問題は情報量の少なさではない。文脈の欠如だ。天気が雨なら屋内に絞る、子どもが0歳なら授乳室必須、外出できる時間は3時間まで——そういう今日固有の文脈を、検索エンジンは持っていない。

KODOCOは文脈を先に受け取る。年齢・天気・外出可能時間・エリア。その組み合わせに最適な「今日はここ1択」を提示する。情報を減らすことで、行動を促すデザインだ。

子どもとの時間は有限だ。週末の午前中、その2〜3時間を「選んでいる時間」に使わせない——それがKODOCOの存在意義だ。

— Tech Stack
Vanilla JS Supabase PostgreSQL kodoco.jp PWA Context Engine
— Key Features
  • ◦文脈入力 — 天気・子の年齢・外出可能時間・エリアを入力して提案を受け取る
  • ◦1スポット提案 — 選択肢を出さない。「今日はここ」1つだけを返す設計
  • ◦子連れフィルタ — 授乳室・おむつ台・駐車場・雨天可など子連れ条件で絞り込み
  • ◦スポット登録 — ユーザーが体験したスポットを投稿・蓄積できるCGMモデル
  • ◦マイリスト — 気になるスポットをブックマーク、次の外出候補として管理
  • ◦パスワードリセット — メール認証連携、Supabase Auth によるセキュアなPW管理
  • ◦独自ドメイン kodoco.jp — 2026年5月取得。DNS / CNAME / OGP 全対応
  • ◦キャラクター「こどこ」 — 緑と温かみをまとったオリジナルキャラクターが案内役
— Design Principle
Context First Less is More Decision Fatigue Zero Family UX
