MOTHERSHIP

設計の原本から、Figmaにも、コードにも。

ひとつの設計データ(JSON)を唯一の原本にして、AIがそこから本物のFigmaノードと本番コードへ"発進"させる。判断は人、翻訳はAI。手を最初から動かさなくていい——AIと人が互いに刺激しあうための、母艦。

開発中 · No-MCP · Local
Key Visual — 仮 / Midjourney差し替え予定

— How it works

mothership.json ← Claude Code が "コードを書くのと同じやり方" で編集 ├─► Figma … プラグインがネイティブノードを生成（テキスト/オートレイアウトのまま編集可） ├─► コード … HTML / React（予定） └─► SVG … イラスト用の補助出力（予定）
— 01

原本はファイル

設計の唯一の原本は1つのJSON。Claude Code がチャット越しに直接書き換える。MCPもSaaSも要らない。

— 02

relayで橋渡し

ローカルの中継が mothership.json を監視し、開いているFigmaプラグインへライブ送信。

— 03

Figmaに直接

本物の編集可能なFigmaレイヤーが即生成。SVG貼り付けと違い、強いFigmaユーザーがそのまま触れる。

— Mothership JSON

{
  "tokens": { "colors": { "accent": "#a89060" } },
  "root": {
    "type": "frame", "name": "Screen", "fill": "@colors.accent",
    "layout": { "mode": "vertical", "gap": 20, "padding": 28 },
    "children": [
      { "type": "text", "text": "体験を、翻訳する。", "font": { "size": 26, "weight": 700 } }
    ]
  }
}

— なぜ Mothership か

  • No-MCP。 原本がただのファイル。AIがネイティブに編集できる。
  • 1フォーマット → Figmaネイティブ ＋ コード の両出力。 どちらか片方ではなく、両方。
  • ローカル / 所有物。 ベンダーロックなし。自分の手元で回る。
  • 思想に乗る。 設計＝コード＝Figma は同じ成果物。木下スタジオの体験翻訳の延長。
